1.1 workflow就是一端固定好的环节预设，有点像面向过程编程，每一个环节下一步要求LLM做什么或者调用什么工具，都写死在流程里。即便有LLM自主决策下一步跳转哪一个branch，branch有多少种情况也是写死的。例子就是比如说Agent里面有的模型路由，这个问题需要路由到能力强的，中等的，还是弱的模型，可以由LLM calling的结果决定，但本身只有3挡，也就是3种选择，这里的选择行为是固定的，我这里强调的就是选择模型，然后把提示词放入那个模型这个2step workflow，后续执行肯定又回归了Agent的自主决定。
1.2 Agent就是一个对于最终目标，中间过程与判断不设置固定步骤数或固定逻辑行为的架构模型。比如说coding agent，你让他实现一个网页，具体网页风格，使用的技术，文件架构都是不固定的，Agent会自主规划目标，反思，修改目标，直至最终实现，或者超过限制后明确拒绝。换一个粒例子的话，比如说助理Agent，像最近的Grok Bot和Dots，你给一个目标：帮我预定周末去海边的酒店，预算是500以内，那么它通过什么方式获取酒店信息，如何对比选择，以及通过什么方式预定（MCP，或者网页表单填写），都是不固定的，最终实现是Agent自主决定的。

2. Though和Action都是由LLM去产生的，也就是模型，Observation则是Action的输出反馈，也就是程序。

## 追问（2026-10-22，Claude Code 批改）

整体通过：workflow 与 agent 的区分抓住了"流程由谁决定"，ReAct 三者归属正确，最后一行的执行顺序也对。下面两处还不够扎实，带着它们进阶段 1。

**追问 1（workflow 与 agent 的边界）**
1.1 里你说路由之后"后续执行肯定又回归了 Agent 的自主决定"。这句不一定成立：路由选完之后，执行的可以只是一次普通的 LLM 调用。
另外判断一下：一个流程是"生成代码 → 跑测试 → 失败就把报错交给 LLM 再改，最多 5 次"。它有循环、有 LLM 根据反馈修改，**这是 workflow 还是 agent？** 用你 1.1 / 1.2 里的标准说明理由。

是workflow，因为每一个环节下一步要求LLM做什么或者调用什么工具，都写死在流程里，即便是重复5次也是，这里就是一个很固定的3step 的 Loop循环，成功就break。

**追问 2（ReAct 的实现细节）**
你写了"程序解析这行字符串、调用接口、把返回文字追加为 Observation"。但模型本来是会一直往下写的：**如果程序不在模型写完 `Action: ...` 那一行后让它停下来，会发生什么？** 程序是用什么办法让它停下的？这个问题的答案，正是阶段 1 里 stop reason 和原生 tool calling 要解决的事。

不停下，则外围程序无法接管，因此就不会产生有效的观察，而是LLM在自说自话的“幻觉”。程序则用静态代码，根据输出格式约定，进行正则分析。

（小问题：1.2 里"修改目标"建议改成"修改计划"。agent 可以调整做法和子目标，但不应该改掉用户给的目标。订酒店的例子里，哪一步你绝对不希望 agent 自主决定？这个问题第 14 阶段会回来。）
